# ui-feature-review

- Status: completed
- Captured: 2026-08-20

Prioritized findings (read-only inspection; confidence reflects direct code evidence):

P0 / high confidence
1. Translate tool is wired to crash/fail when invoked from the IME. `NovaBoardService.openTextAction()` calls `startActivity(Intent.createChooser(...))` without `FLAG_ACTIVITY_NEW_TASK` (`app/src/main/java/com/novaboard/ime/NovaBoardService.kt:244-264`). A service context cannot start an Activity without that flag; the More button explicitly adds it at lines 191-195, highlighting the inconsistency. The advertised Translate action therefore is not usable and can throw AndroidRuntimeException.
2. Voice typing has no runtime microphone permission flow. Manifest only declares `RECORD_AUDIO` (`app/src/main/AndroidManifest.xml:4`), while `startVoiceInput()` immediately creates/starts `SpeechRecognizer` (`NovaBoardService.kt:537-590`) and catches neither SecurityException nor permission denial. On modern Android, first use can fail/crash or always report an error rather than request permission. High confidence.
3. “Number row” preference is ignored on symbols pages. Service chooses `lettersWithoutNumberRow` only when entering letters (`NovaBoardService.kt:143-151`), but `KeyboardLayouts.symbols` always includes `numberRow` (`KeyboardModel.kt:147-155`). Users who disable Number row still see it after tapping 123. High confidence.
4. Three settings are exposed but have no implementation: `SHOW_PREDICTIONS_AFTER_FLOW`, `SYSTEM_GRAMMAR_CORRECTIONS`, and `SYSTEM_GRAMMAR_SUGGESTIONS` are declared/defaulted and rendered in Settings (`KeyboardPreferences.kt:28-30,55-57`; `MainActivity.kt:162-179`), but have no reads outside those declarations/UI (confirmed by repository search). Toggling them cannot change behavior. High confidence.

P1 / significant user-facing failures
5. Emoji-on-enter is applied unconditionally to every editor, not only chat apps as the setting summary promises. `onEnter()` opens emoji panel whenever `EMOJI_ON_ENTER` is true (`NovaBoardService.kt:477-481`), with no `EditorInfo` input type/package check. In email, password, terminal, etc. Enter stops submitting/newline and instead opens the panel. High confidence.
6. Emoji insertion bypasses typing state. `onEmoji()` commits directly (`NovaBoardService.kt:503-513`) and the `EmojiPanel` callback only calls `commitText` (`NovaBoardService.kt:508-511`); it does not update `currentWord`, `previousWord`, autocorrect bookkeeping, or suggestions. After inserting emoji, predictions/current-word tracking can describe stale text. High confidence.
7. Emoji panel contains visibly fake/nonfunctional controls: header labels `GIF ✦ ▧ ◉` are a plain `TextView` with no click listener (`EmojiPanel.kt:181-188`), and the category “⌕” tab is just another static category selecting `EmojiData.all` (`EmojiPanel.kt:229-255`). GIF/search/media affordances imply functionality but do nothing. High confidence.
8. Clipboard history persists image content URIs without a durable grant and later assumes they remain readable. It stores only `item.uri.toString()` (`ClipboardHistory.kt:67-79,118-135`), persists it across service/process lifetime, and only requests permission during paste (`NovaBoardService.kt:211-234`). URI grants from clipboard providers may expire/revoke; persisted entries can render blank (`ClipboardAdapter.kt:31-37`) and fail paste. This is an unsafe assumption, especially after reboot/provider changes. Medium-high confidence.
9. Clipboard capture drops valid text clips whose description is not `MIMETYPE_TEXT_PLAIN` (e.g. HTML-only or other text representations), despite `ClipData.Item.text` being available. The `when` requires `desc.hasMimeType(MIMETYPE_TEXT_PLAIN)` (`ClipboardHistory.kt:72-79`). User copies text from rich/web apps and it may never appear in history. Medium confidence (provider MIME behavior varies).
10. Clipboard history JSON loading is not resilient to malformed/unknown persisted entries. Only JSONArray construction is guarded; `getJSONObject`, `getLong`, `valueOf`, etc. can throw (`ClipboardHistory.kt:138-160`). One corrupted/old item can prevent `ClipboardHistoryManager.start()` and therefore keyboard creation. Medium-high confidence.
11. Backspace undo-autocorrect assumes the cursor is still immediately after the exact replacement. It deletes `lastAutocorrectReplacement.length` at the current cursor and restores original (`NovaBoardService.kt:458-469`), without checking cursor position, intervening input, selection, or editor changes. Any cursor movement or subsequent edit can delete unrelated text. High confidence.

P2 / interaction/layout correctness
12. Key preview popup is positioned using `preview.measuredWidth` before the PopupWindow content is measured (`KeyboardView.kt:306-333`); width is commonly 0 at that point, so preview is offset rather than centered. Medium-high confidence.
13. Long-press symbol picker is accidentally disabled whenever key popups are disabled: `schedulePopup()` returns if `!keyPopups || !longPressSymbols` (`KeyboardView.kt:293-295`). Settings present “Key pop-ups” and “Long-press symbols” as separate controls (`MainActivity.kt:81-97`), so turning off tap previews also suppresses the separately enabled long-press feature. High confidence.
14. Quick-delete implementation does not match its own summary (“select and delete text”): horizontal drag from backspace immediately deletes the prior non-whitespace word (`KeyboardView.kt:250-258`; service `NovaBoardService.kt:520-528`), with no selection. If the intended UX is select-then-delete, the interaction is missing. High confidence as a contract mismatch.
15. Emoji font option “Latest Google Emoji” does not provide a Google emoji font/resource; both branches use platform typefaces (`EmojiPanel.kt:278-283`: `sans-serif-emoji` vs `Typeface.DEFAULT`). Selecting Google may produce no meaningful visual difference and cannot deliver the advertised latest set. High confidence.
16. Key model’s number row is represented as ordinary CHAR keys and is present in every symbols primary page; there is no preference-aware symbols variant or layout transformation (`KeyboardModel.kt:41,147-155`). This reinforces the settings failure and makes layout assumptions hard-coded. High confidence.
17. MainActivity’s `PreferenceSpec.default` is never used (`MainActivity.kt:250-413`), so the UI has duplicated defaults that can silently diverge from `KeyboardPreferences.defaults`; currently reset behavior relies only on storage clear. Medium confidence maintainability/unsafe assumption.

Additional evidence: `KeyboardView` filters the emoji key only at hit-rect construction (`KeyboardView.kt:175-197`), so dedicated-key off is handled visually/hit-test-wise, but the setting does not offer an alternate emoji access route except the tools/panel affordances; `EmojiPanel` is only opened through that key or the unconditional enter path (`NovaBoardService.kt:503-514`).
