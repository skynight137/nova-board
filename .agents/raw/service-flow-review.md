# service-flow-review

- Status: completed
- Captured: 2026-08-20

Prioritized review (no files edited; evidence is static source inspection):

1. **Voice typing can crash/fail on first use due to missing runtime permission (High, ~0.95).** `AndroidManifest.xml:4` declares RECORD_AUDIO, but there is no `requestPermissions`/permission-result flow anywhere in `MainActivity` or `NovaBoardService`. `NovaBoardService.kt:537-590` calls `SpeechRecognizer.createSpeechRecognizer` and `startListening` unconditionally after only checking recognizer availability. On Android 6+, a denied/not-yet-granted microphone permission can produce SecurityException or an immediate error. Fix: request RECORD_AUDIO from the settings Activity (with rationale/error state), and guard `startVoiceInput` with `checkSelfPermission`, reporting a clear action to the user; avoid requesting from the IME service itself.

2. **IME session state is not cleaned up on input finish (High, ~0.93).** `NovaBoardService.kt:96-103` only dismisses emoji, stops clipboard, and destroys speech in `onDestroy`; there is no `onFinishInput`/`onFinishInputView`. `toggleVoiceInput` starts recognition at `:547-591`, and `onResults` commits to `currentInputConnection` at `:571`; if the editor/app changes while listening, recognition can commit text into the new field. Clipboard/emoji overlays can also survive editor transitions. Fix: implement `onFinishInputView` (and/or `onFinishInput`) to stop voice, dismiss `clipboardPanel` and emoji, reset `currentWord`, previous/autocorrect state, and disarm hotkeys; make callbacks validate the active session.

3. **Shift state leaks between fields (High, ~0.9).** `onStartInputView` at `:135-141` resets suggestion state but never calls `keyboardView.setShiftState(false)`. Auto-capitalization at `:406-415` or a user shift can leave shift enabled, so opening another field starts uppercase unexpectedly. Fix: reset shift/caps-lock on `onStartInput`/`onStartInputView`; derive initial shift from `EditorInfo`/sentence context if desired.

4. **Translation action does not implement replacement and often translates the wrong text (High, ~0.9).** `NovaBoardService.kt:244-264` obtains selected text, or silently falls back to the last word before cursor (`:247-249`), then launches `ACTION_PROCESS_TEXT` with `startActivity(createChooser(...))` at `:253-263`. There is no `startActivityForResult`/activity-result handling and no replacement of the selected range with returned `EXTRA_PROCESS_TEXT`. For the fallback case there is no selection at all, so a translation app cannot reliably replace that word. Fix: only invoke PROCESS_TEXT for an actual selection (or explicitly select/track the preceding range), launch a result-capable flow where supported, and commit/replace returned text while preserving the original selection; otherwise expose “translation unavailable” rather than claiming the action succeeded.

5. **Clipboard image history stores unusable transient URI references (High, ~0.88).** `ClipboardHistory.kt:67-79` persists only `item.uri.toString()`; `:118-135` writes it to disk. On a later IME session/reboot, the clipboard provider's URI grant may be gone. `ClipboardPanel` renders it via `setImageURI` (`ClipboardAdapter.kt:31-40`), and paste requests access only at paste time (`NovaBoardService.kt:211-229`), where `requestPermission()` may already fail. Fix: copy image data into app-private storage when capturing (or take persistable permission when the provider supports it), clean up deleted/unpinned files, and handle inaccessible items by removing/marking them unavailable.

6. **Clipboard listener/panel lifecycle leaks callbacks and allows stale panels (Medium, ~0.85).** Every `ClipboardPanel.show` installs `history.setOnChangedListener { refresh() }` (`ClipboardPanel.kt:91-92`), but `dismiss()` at `:111-114` never unregisters it. Opening the panel repeatedly replaces the listener without dismissing an existing popup (`NovaBoardService.kt:198-201`), and old panel roots/listeners remain referenced by the history manager. Fix: provide `removeOnChangedListener`/clear listener on dismiss, dismiss an existing panel before creating one, and guard refresh after dismissal.

7. **Typing model becomes incorrect after external cursor/selection edits (Medium-high, ~0.86).** `currentWord` is maintained solely by keyboard callbacks (`NovaBoardService.kt:359-365`, `:472-474`) and is not synchronized in `onUpdateSelection`/`onStartInput`. Cursor arrows (`:289-293`, `:516-518`), selecting text externally, app-side edits, and clipboard insertion do not update it. Subsequent suggestion picks and autocorrect call `deleteSurroundingText(currentWord.length, 0)` (`:331-337`, `:427-446`) and may delete unrelated text. Fix: implement `onUpdateSelection` and invalidate/rebuild the composing word whenever selection/cursor moves; use `setComposingText`/tracked cursor bounds or verify surrounding text before deletion.

8. **Undo-autocorrect state is not cleared/updated consistently (Medium, ~0.82).** `replaceWithPrediction` stores `lastAutocorrectReplacement = replacement + suffix` (`NovaBoardService.kt:445-449`), then backspace deletes that entire string and commits the original (`:461-469`), but leaves `currentWord` empty (it was cleared after punctuation/space). The next backspace therefore deletes one character from the restored original while the model still thinks no word exists; undo can also fire after intervening cursor/editor changes because state is not invalidated. Fix: track the exact inserted range, restore `currentWord` to the original word, and clear undo state on any non-backspace edit, selection change, or input-session transition.

9. **Theme changes do not reliably recolor an already-running keyboard (Medium, ~0.78).** `MainActivity.kt:238-247` changes AppCompat default night mode and recreates only the Activity. The IME service calls `ThemeManager.applyStored` only in `NovaBoardService.onCreate` (`:81-87`), while `KeyboardView` creates its Paint colors once in property initialization (`KeyboardView.kt:72-88`). The service preference listener (`NovaBoardService.kt:66-79`) reapplies keyboard preferences but does not recreate/re-resolve theme paints. Fix: observe the theme preference in the service, apply the mode, and recreate/rebind the input view or add a `refreshTheme()` that reloads all colors/invalidates the view.

10. **Clipboard history does not record the existing primary clip at service startup (Medium-low, ~0.75).** `ClipboardHistory.start()` only loads persistence and registers `OnPrimaryClipChangedListener` (`ClipboardHistory.kt:48-51`); it never calls `addFromClipData(primaryClip)`. Thus a clip copied before NovaBoard starts is absent until copied again. Fix: after registering/loading, intentionally import `primaryClip` once (with duplicate protection), subject to the platform/privacy policy.

11. **Keyboard sound setting plays two sound mechanisms per key (Low-medium, ~0.7).** `KeyboardView.kt:385-392` calls both `AudioManager.playSoundEffect` and a `ToneGenerator` beep for every key when SOUND_ON_KEYPRESS is enabled. Fix: select one mechanism and release/cancel ToneGenerator on lifecycle teardown (also cancel pending long-press callbacks in `onDetachedFromWindow`).
